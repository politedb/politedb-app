## Findings

1. **P1 — src/screens/connection/nav/DbObjectsManagerPane.tsx:368; integration with src/components/editor/SqlEditorPane.tsx:401–427,815–821: actual editor changes are delayed and persisted.** controlledContent skips disk loading but does not change Monaco change handling: a 700 ms timer awaits saveSqlDraft before invoking onCommitContent. Until then the object store contains old SQL. Immediate Mod+S can submit stale SQL, immediate close/reopen depends on delayed persistence, and text typed during execution need not reach the store before completion. Object SQL still reaches draftSqlSave and its filesystem service, violating no-persistence requirements. Editor storage/model identity also lacks screen-tab scope for identical object ids across connections. Fix: deliver controlled object changes synchronously into the tab-scoped store, bypass all SQL-draft persistence for these editors, and scope Monaco identity by screen tab/key. Preserve ordinary SQL-editor behavior. Regression: real editor/Monaco event harness covering type then immediate save/close/reopen, typing during save, two tabs with the same object id, and zero draft-save invokes. Current pane tests replace the editor with a static div and cannot verify this contract.

2. **P1 — src/screens/connection/hooks/useLoadDbObjectDefinition.ts:49,63–79: no captured revision guard.** Generation and render identity allow an older definition fetch to overwrite a newly saved clean draft: reopen loaded v1 with a fetch pending, type and save v2, then resolve the older response as v1. markSaved retains generation; applyDefinition now sees a clean draft and replaces SQL/baseline with v1. No cleanup invalidates an unmounted hook request either. Fix: capture and validate revision, generation and live tab/connection lifetime, and invalidate on cleanup. Regression: deferred fetch resolved after typing plus save, edits returning to baseline, unmount, and discard/recreation; no stale SQL/baseline/conflict writes.

3. **P1 — src/screens/connection/lib/objectSave.ts:107–113: missing detection is wired only after executable object saves.** This is the sole production syncMissing caller. Ordinary metadata/sidebar refresh and toast refresh never reconcile missing/reappearing objects. A dirty externally dropped function stays executable after refresh; its CREATE OR REPLACE can recreate it on the next save. Missing drafts also stay blocked after ordinary refresh shows them again. Fix: reconcile at the shared successful complete metadata-refresh boundary; failed/loading/partial refreshes must not reconcile. Regression: external disappearance followed by normal refresh blocks DDL and retains a recoverable sidebar draft; later reappearance clears missing; clean disappearance and failed-refresh retention use production callers, not direct store calls.

4. **P1 — src/screens/connection/lib/objectSave.ts:108–113: post-refresh draft writes lack lifecycle and outcome-identity guards.** Only outcome.ok is checked. Reset/reconnect and new drafts during the await let old metadata mark replacement drafts missing or delete clean ones. Returned connectionId/metaKey are ignored; tests accept unrelated metaKey m. Toast Open correctly has stronger checks, but this other async write does not. Fix: capture epoch/connection/scope and revalidate immediately before reconciliation; skip stale lifetimes. Regression: deferred refresh across same-id reset, reconnect and replacement drafts; wrong connection/metaKey outcomes produce no draft/window writes.

5. **P2 — src/stores/screen.ts:417–432: reset leaves object drafts alive.** resetTabs bumps epochs but clears no drafts; direct removeTab also relies on external wrappers for object cleanup. resetTabs([]) leaves closed work contributing to quit warnings, and reused tab ids inherit old drafts. Fix: clear drafts at authoritative removal/reset boundaries, including clean/windowless work; invalidate pending completions. Regression: seed clean/dirty edits and creates across tabs, reset/remove through store actions and reuse ids; verify cleanup, warnings and unrelated-tab isolation.

6. **P2 — src/screens/connection/hooks/useConnectionActions.ts:730–748,515–518; src/lib/objectEditorDraftCache.ts:71: skipped work and conflicts never reach save review.** collectSkippedObjectDrafts has no production caller. Only-empty/missing work silently returns before opening review; mixed saves omit skipped work. Conflict appears only in the pane and is never repeated in review, allowing a closed conflicted draft to be overwritten without the approved warning. Fix: pass pending/skipped/conflict details into review, allow review of non-executable pending work, and label what remains unsaved. Regression: review closed empty creates, missing/conflicted edits and mixed table/object work; assert counts/reasons/warnings, execution exclusion and retained pending state.

7. **P2 — src/stores/screen.windows.test.ts:55–69: lifecycle test leaves async imports past teardown, failing both suites.** Real addTab/removeTab queue connection-log imports while the test mocks only persistence. Both runs below report EnvironmentTeardownError originating here despite passing assertions. Fix: mock/isolate the log boundary or reliably await lifecycle side effects and teardown; do not suppress unhandled errors. Regression: focused and full runs exit 0 without unhandled errors. Expand lifecycle coverage: objectWindows.test.ts's test titled closed/reset/reconnected never actually calls resetTabs; helper-only tests miss findings 1–6.

### Findings

1. **P1 — src/stores/objectDrafts.ts:250 (also :305–310), src/screens/connection/hooks/useLoadDbObjectDefinition.ts:79: late definition clears a newer missing-object verdict.** Start a definition fetch for an already dirty edit; the database definition differs from its baseline. Before that response arrives, complete metadata refresh confirms the object was dropped and sets missing=true. syncMissing does not change revision/generation, so the older response passes both guards; applyDefinition sets conflict=true and missing=false. The draft becomes executable again, allowing CREATE OR REPLACE to recreate the dropped object despite the approved missing-object block. Reproduced directly against the transpiled current store: after metadata `{missing:true, executable:false}`; after late definition `{missing:false, executable:true, conflict:true}`. **Fix:** make metadata membership authoritative; definition completion must not clear missing (only a successful current complete object-list refresh should), or invalidate definition responses when membership changes. Also validate live tab/connection/epoch at definition commit. **Regression test:** deferred real loader response containing a changed definition; successful real metadata refresh drops the object first; resolve definition and assert missing remains true, SQL/baseline retained, collector excludes DDL and sidebar draft remains recoverable. Add same-id reconnect away-and-back before resolution.

2. **P2 — src/screens/connection/ConnectionScreen.tsx:742–746: save notices freeze while the reviewed/executed work can change.** The assumption that drafts cannot change while review is shown is false: pending definition requests, metadata refreshes and in-flight saves can finish behind the modal. objectSql/objectChangeSummary are recomputed on parent renders, and confirmation collects live drafts, but objectSaveNotices depends only on showSaveDialog. A definition can discover a conflict after review opens without ever showing the required overwrite warning; a missing/reappearing object can leave stale skip reasons or a stale skipped-only notice that keeps Confirm disabled after SQL becomes available. **Fix:** subscribe to the reviewed tab's draft state and derive SQL, summaries, notices and Confirm eligibility consistently from current state, or explicitly bind confirmation to one immutable reviewed snapshot and require renewed review after changes. **Regression test:** open actual review before deferred definition/metadata resolution; introduce conflict, disappearance and reappearance while it stays open; verify warning/reason, executable SQL and Confirm update together and confirmation cannot execute newly conflicted work without its warning. Existing isolated dialog tests only pass static props.

### Findings

1. **P1 — src/screens/connection/nav/DbObjectsManagerPane.tsx:379–382: the synchronous editor callback can drop the latest SQL change.** It compares each event with `sql` captured at the previous render instead of the current authoritative draft. With rendered SQL `v1`, two model events before the next render (`v2`, then `v1`, such as a batched edit and undo) store `v2` and then skip `v1`. Save/preview/close-reopen therefore use the intermediate text; the controlled editor can also echo that text back over the user's final edit. This leaves the round-1 synchronous-text invariant incomplete even though persistence/debounce were fixed. **Reproduction:** a read-only Node/TypeScript harness transpiled the actual pane and store, stubbed rendering/hooks/I/O, obtained the actual rendered onCommitContent callback and invoked those two events without rerender. Result: `{lastEditorEvent:"v1", storedSql:"v2", pending:true}`. **Fix:** deliver every model event to setSql unconditionally (the store already deduplicates against its live SQL), or compare against the live scoped draft. **Regression test:** mount the pane with a real editor/Monaco stand-in; emit edit then return-to-rendered-text in one act before rerender, immediately inspect/save and close/reopen; assert final store/editor SQL and preview agree, returning to baseline is clean, and no SQL-draft persistence occurs. Cover both create and edit drafts and a return to a previously dirty rendered value.
