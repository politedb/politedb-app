## Findings

1. **P2 — Give keyboard-opened menus focus.** `src/components/AppHeader.tsx:557`, `src/components/AppHeader.tsx:564`. Both ContextMenu instances omit `autoFocus`, whose default is false. Focus stays on the tab after Shift+F10/ContextMenu, or on the + button after keyboard activation. ArrowDown cannot navigate the menu; Enter on the originating tab switches connections instead of activating a menu item, and Delete still closes that tab underneath its open menu. Temporary DOM probes reproduced the retained focus, ignored ArrowDown and Enter switching with the menu still open. **Fix:** enable the existing ContextMenu focus/restore behavior for both menus; preserve a sensible surviving focus target when an action removes its opener. **Regression tests:** keyboard-open both menus, assert first enabled item receives focus, navigate/activate with arrows and Enter, dismiss with Escape and verify focus restoration; cover closing the opener.

2. **P2 — Make tabindex follow the roving focus.** `src/components/AppHeader.tsx:193`, `src/components/AppHeader.tsx:394`. Arrow/Home/End only call `focus()`, while `tabIndex=0` remains tied to the selected connection. After moving from selected A to unselected B without activating it, B is focused but still has tabindex -1 and A remains 0. Leaving and re-entering the strip returns to A rather than the last focused tab; backward traversal can also revisit A within the strip. This does not implement the approved roving tabindex contract. A temporary DOM probe confirms `[0, -1, -1]` remains unchanged after ArrowRight focuses B. **Fix:** track the focused tab separately from selection, update the single zero tabindex on focus/navigation, reconcile it when tabs disappear, and retain manual Enter/Space activation. **Regression tests:** verify tabindex after every navigation key, Tab/Shift+Tab exit/re-entry, external connection switching and focused-tab removal.

3. **P2 — Include the safety picker in the open-menu shortcut guard.** `src/layout/index.tsx:76`; picker: `src/screens/connection/workspace/MenuBar.tsx:542`. The new tab-switch handler relies on `isModalDialogOpen`, which recognizes only `[aria-modal="true"]` or `[role="menu"]`. The safety picker renders an unlabelled div of buttons, so opening it from either MenuBar or the new status badge does not block Cmd/Ctrl+1…9 or Ctrl+Tab. Connections can switch underneath that open picker, contrary to Batch 2. This is a new shortcut integration omission involving existing picker markup; it is not evidence that SQL lock enforcement was bypassed. **Fix:** expose/register this picker as an open menu through the shared guard, with appropriate menu keyboard/focus behavior. Audit other custom menus reached from a connection for the same omission. **Regression tests:** open the actual picker, dispatch each tab-switch shortcut and assert the active connection is unchanged; dismiss it and assert switching resumes. The temporary markup probe confirms the current guard returns false for the picker shape; actual MenuBar/MainLayout integration remains untested.

4. **P2 — Reveal the active tab when the strip narrows.** `src/components/AppHeader.tsx:159`. ResizeObserver only recomputes fades. The scroll-into-view effect depends on active ID and tab count, so narrowing the window with an active tab near the right edge can clip/hide it indefinitely until selection/count changes. The new resize path does not satisfy keeping the active connection visible. A temporary observer probe confirms its callback never invokes scrollIntoView. **Fix:** reveal the active tab when the strip viewport changes, then recompute fades; keep intentional wheel scrolling independent. **Regression test:** select a rightmost tab, shrink the viewport without changing selection/count and assert its bounds remain inside the strip, with correct fades.
