## Decisions (resolved by the human 2026-10-26)

- **TBD-1 → separate store.** A new non-persisted `useObjectDraftStore`, scoped by connection screen-tab id.
- **TBD-2 → keep untouched create drafts.** Closing an untouched "new function" tab keeps the draft (like a new table). (Pending/execution rules are defined by S1 below, which supersedes the original "non-empty SQL counts as pending" wording.)
- **S1 (2026-10-26, after Codex R1–R4) → simplify create saves and save concurrency** ("đồng ý, viết lại plan"):
  - a create draft counts as pending work for its whole life (until saved or discarded); SQL emptiness only decides whether it can execute;
  - a successful CREATE removes the draft (never replayed) and closes its window (see S2 for what follows; no SQL parsing, no guessing, no in-place re-keying);
  - one save at a time per connection screen tab (Mod+S while saving is ignored); create drafts are read-only while being saved; edit drafts stay editable and newer text stays pending; a per-draft generation token makes stale completions no-ops after discard or re-creation;
  - "missing" only after a successful complete metadata refresh; cleared when the object reappears.
- **S2 (2026-10-26, after Codex V4-1) → never open the created object automatically** ("Đóng tab + toast có nút Mở"): after a successful CREATE the create window closes and a toast says "Created <kind> <name>" with an **Open** action. Clicking Open looks the object up at that moment (exactly one kind/schema/name match in a successful fresh refresh of the toast's connection screen tab) and opens it through the normal opener; no match or several → "Open it from the Objects sidebar". Behavior change: the create tab no longer turns into the object's editor; one extra click opens it. `showToast` gains an optional `action: { label, onClick }`; existing toasts are unchanged.
- **TBD-3 → keep the draft and warn.** When a fetched definition differs from the draft's baseline, keep SQL and baseline untouched, show a conflict notice in the pane, and repeat it in the save review. Detection on fetch only (no polling, merge or optimistic locking).

## Goal And Visible Result

1. Closing an object tab never loses its draft; reopening shows it (dirty state included). Closed create drafts stay in the Objects sidebar and reopen into the same draft.
2. Mod+S saves closed object drafts too, exactly once; discard removes/reverts them; closing a connection tab and quitting warn about them.
3. Closing the active tab activates its right neighbor among the survivors, else the left one; bulk closes never leave a dangling active id.
4. Tabs with pending work show an accessible "●" marker; sidebar, marker, warnings, review counts and Mod+S use one shared predicate.

## Design

### Phase A — Object draft store and editor (D1, D2)

- `src/stores/objectDrafts.ts` (`useObjectDraftStore`, not persisted):
  `drafts: Record<screenTabId, Record<draftKey, ObjectDraft>>`, each draft `{ key, mode: "create" | "edit", kind, form: { schema, name, tableName }, sql, baselineSql, item?, revision, generation, saving, conflict?, missing? }`.
  - Create: `baselineSql` = generated template at open (informational); edit: `baselineSql` = definition as fetched.
  - `revision` increments on every SQL/form/kind change; `generation` changes whenever the draft is discarded, reverted or re-created, so a save completion carrying an old generation does nothing.
  - Every selector and action takes the screen-tab id (bound once per connection screen), including `openObjectDraft`.
- Keys: one module `objectDraftKey.ts` maps `draftKey ↔ windowId` without parsing object ids (window id = `db-object-manager:` + key; key = `obj:` + objectId or `new:` + random). A create key never changes with kind/name/schema.
- Opening (`useConnectionWindows.openDatabaseObjectsManager`):
  - existing object: focus/create window for `obj:<id>`; create the edit draft only when none exists; never write `dirty`.
  - new object: seed the create draft synchronously before the window renders (immediate save/close is deterministic).
  - new `openObjectDraft(key)` reopens a closed create (or edit) draft by key.
- Editor (`DbObjectsManagerPane`, `useLoadDbObjectDefinition`):
  - SQL and form state read from the store and written synchronously on change; local state only for transient UI/loading.
  - Loader guards: a response is applied only if the screen tab, draft key, connection, `generation` and `revision` all still match the request (generation covers discard/re-creation that reuse a key or revision). Definition-fetch failure leaves the draft as it is and shows the error; it never seeds an empty definition.
  - Loader: never overwrites pending work. A fetched definition refreshes a **clean** edit draft's SQL and baseline (the intended exception); for a **dirty** edit draft it only sets `conflict` when it differs from `baselineSql` (TBD-3). Create drafts are never touched by the loader. Stale responses (different screen tab, key, connection, or a newer `revision` since request) are ignored.
  - Remove the dirty-transition baseline logic (`DbObjectsManagerPane.tsx:528–550`) and `pendingObjectEditorResets`; save/discard are explicit store actions (`markSaved`, `revert`, `remove`).
- `closeWindow` no longer clears object drafts.

### Phase B — Save, discard, warnings, cleanup (D3, D4)

- Shared predicates in `objectDrafts.ts`, reused by collector, counts, marker, sidebar, warnings and loader:
  - `hasPendingWork(draft)`: create → always true (S1; kept until saved or discarded, form-only and empty-SQL drafts included); edit → `sql.trim() !== baselineSql.trim()` (missing edits included).
  - `canExecute(draft)`: `hasPendingWork` and `sql.trim() !== ""` and not `missing` and not `saving`. Empty-SQL creates and missing edits still warn but produce no DDL; the save review lists them as "not saved" with the reason.
  - Table side: extract/reuse the existing patch and valid-new-table predicates from `tabDirty.ts`.
- `collectPendingObjectSaveEntries(screenTabId)` reads drafts read-only (no seeding), regardless of open windows; one entry per executable draft.
- One save service used by the global Mod+S path and the pane's registered save, one run at a time per screen tab (a second Mod+S while running is ignored):
  - snapshot `{ screenTabId, connectionId, key, generation, revision, mode, kind, form, item, sql }` before awaiting; statements are built from the snapshot only;
  - create drafts are marked `saving` for the run: create SQL, schema/name/table/kind controls and Regenerate are read-only;
  - success, edit → if the draft's generation still matches: baseline = submitted SQL; newer revisions stay pending;
  - success, create → the DDL has run; from here no failure restores the draft or goes through the failure branch:
    1. if the draft's generation still equals the snapshot's, remove the draft and close its window if open (an inactive window closes without moving focus; an active one hands focus to its neighbor per Phase C); on a mismatch (discarded or re-created meanwhile) leave the current draft and windows alone;
    2. refresh metadata so the sidebar lists the new object (result not needed for any window action);
    3. show the S2 toast with its Open action, bound to the snapshot's screen tab id and connection id;
    4. release the screen tab's save lock (also on every error path).
       The save service opens no window and seeds no draft.
- **Open action (V5-1), a click-scoped navigation that reads live state, never the save-time closure:**
  1. at click: resolve the target screen tab from `useScreenStore.getState()` by the toast's screen-tab id and check its connection matches; capture its lifecycle `epoch` (new: `screen.ts` keeps `tabEpoch[screenTabId]`, incremented when that tab is closed, reset (`resetTabs`) or reconnected); absent/mismatch → sidebar hint, nothing written. Same ids recreated **before** the click are fine: the click is fresh authorization for a lookup in the currently matching tab;
  2. request a fresh refresh for that target (V3-1 contract);
  3. after the await: require `ok`, the returned connection/metaKey equal to the target's, and the target's `epoch` and connection unchanged; otherwise sidebar hint, no window/draft/focus write. The active screen tab having changed meanwhile does not retarget the action (it still targets its own screen tab);
  4. exactly one kind/schema/name match → `openObjectInScreenTab(screenTabId, object)`, a store-level opener that reads the current window list and draft state at call time (focus an existing `obj:<id>` window, else add one; never touch an existing draft); `useConnectionWindows.openDatabaseObjectsManager` delegates to it. Zero or several matches → sidebar hint.
     Toast: Open is a real button (keyboard reachable, accessible name), disabled while its action runs (repeated clicks ignored), the toast stays until the action settles, async rejection → sidebar hint. Action-less toasts are unchanged.
  - failure → draft unchanged (`saving` cleared); mixed table/object outcomes reported per part (no claim of atomicity across them);
  - generation mismatch or tab closed during the run → completion makes no draft change (the DDL already ran; a notice says so);
  - lock / safe-mode authentication and existing SQL/transaction/capability rules unchanged.
- Discard (`discardObjectDrafts`, hook `discardChanges`, fallback dialog discard, `discardAllConnectionChanges`): creates removed (close window if open), edits reverted; works with zero open windows.
- Warnings: `tabDirty.ts` (including the `dirtyStateByScreen` early return), `src/screens/connection/lib/unsavedChanges.ts` (all tabs, for quit), `connectionTabClose.ts`. The close-tab dialog keeps today's policy (`workspace/UnsavedChangesDialogHost.tsx` → `WarningRefreshDialog`: Discard/Cancel) for the whole pending tab, table and object work together; quit keeps discard-and-quit.
- Cleanup: closing/removing a connection screen tab and reset clear its drafts; table-only helpers (`clearTablePatchChanges`, scoped table clears) do not touch drafts; a successful table save leaves drafts intact.
- **Metadata refresh outcome (V3-1).** `useDatabaseMetadata.refresh` today catches errors and returns cached metadata with `error`; `useSchemaTablesPanel.refreshSchemaAndTables` and the runtime context (`ConnectionRuntimeContext.tsx:44`, `Promise<void>`) discard it; the save path reads `listDatabaseObjects()` separately. Change the boundary to return `{ ok: true, metaKey, connectionId, objects } | { ok: false, error }`:
  - `ok: true` only when that refresh call itself completed without error for the same metaKey/connection; a refresh that was already in flight when requested is awaited and then a new one is started, so the result post-dates the DDL;
  - cached data is never reported as `ok`; callers that ignore the result keep working.
    Used by the S2 Open action and by missing detection only.
- Dropped objects (`useDropDatabaseObject` success): remove that object's draft. External disappearance: set `missing` only after a successful, complete (not loading, not failed, not schema-filtered) metadata refresh for that connection no longer lists it; a dirty missing draft stays listed and warns but cannot execute (Mod+S never recreates it); a clean missing draft is removed; `missing` clears when a later complete refresh lists the object again.
- Sidebar (`LeftNavObjectsPane`): closed create drafts listed under their kind, included in search, counts, unique naming and schema filter (from `form.schema`); dirty edits tinted whether open or not; "missing" drafts listed.

### Phase C — Tab bar (D5, D6)

- `screen.ts`: new `removeWindows(screenTabId, ids, { activate: "neighbor" })` in one state transition: survivors keep order; if the active window survives it stays active; else the nearest survivor to its right in the original order, else to its left, else null. `removeWindow` delegates to it; `replaceWindows` keeps a surviving active id instead of always picking the last. Check other callers of both before changing.
- `useConnectionWindows.closeWindows(ids)` runs per-window cleanup (table cache, SQL last-closed capture, pagination) then calls `removeWindows` once. ×, Mod+W, Close / Others / to the Right / All use it.
  - Example `[A,B,C,D]`, active C, "Close to the Right" on A → active A; Close Others → target; Close All → null.
- `NavigationTabs` marker "●" for table and object windows by the shared predicates (SQL/catalog unmarked); reactive for inactive windows; visually hidden text "Unsaved changes" in the tab's accessible name; close-button hit area unchanged.

## Plan Review

Reviewed by Codex, 2026-10-26. **Changes required before human approval.** D1–D6 address real gaps, but lifecycle, identity resolution, and state ownership need explicit contracts. Keep status DRAFT until Claude revises this plan and the human resolves all three decisions. No application code changed; review based on static inspection, not executed tests.

### Current Behavior: confirmed facts and corrections

- Confirmed: module caches are keyed only by window id; object close deletes both caches; collectors and discard enumerate open windows; sidebar create rows come from open windows; saved-row dirty tint is restricted to the active object; create saves retain their original window id. Tables keep patches/new-table state across window close. NavigationTabs currently has no dirty marker.
- **Edit restoration is already incomplete before closing.** `useLoadDbObjectDefinition.ts:13–70` owns local SQL/baseline and fetches a fresh definition on selection/remount. `DbObjectsManagerPane.tsx:499–518` writes the edit cache but does not hydrate editor state from it. Switching away and back can reload the database definition and overwrite cached edits. Do not describe the edit cache as sufficient restoration today; D1 must fix the loader, not merely replace map accessors.
- **Quit does not delegate to `connectionTabHasChanges`.** `useConnectionQuitGuard.ts` calls `hasAnyUnsavedConnectionChanges` / `discardAllConnectionChanges` in `lib/unsavedChanges.ts`; those independently enumerate table state. D3's “and so … the quit guard” claim is false. Explicitly include that module and its tests in scope.
- **Neighbor selection has two owners today.** `useScreenStore.removeWindow` (`src/stores/screen.ts:177–200`) selects the last survivor, then `useConnectionWindows.closeWindow` repeats selection using captured arrays. `replaceWindows` also selects the last window unconditionally. Hook-only changes are insufficient for reliable bulk close/re-key behavior.
- Existing-object opening explicitly writes `dirty: false` even when focusing an already open window (`useConnectionWindows.ts:220–230`). This can trigger the pane's dirty-to-clean effect, which interprets the transition as save/discard and changes the baseline. This path must stop authoring dirty state.
- Untouched create SQL currently participates in pending SQL/review even with window `dirty: false`; dirty markers, save eligibility, and “has work” are already different predicates. Table close also preserves SQL-tab history/result cleanup behavior that must remain intact.

### Required design revisions

1. **P1 — D1: commit to one authoritative draft, not “derived or kept in sync.”** Store SQL, baseline, create fields, mode and identity in one place. Specify synchronous editor event updates and store subscriptions for pane/sidebar/tabs/review; remove effect-based copying between local SQL, caches and window `dirty`. Keep local state only for transient UI/loading. Replace the pane's dirty-transition baseline logic (`DbObjectsManagerPane.tsx:528–550`) with explicit save/discard operations. Otherwise focus, remount, save completion or discard can silently bless stale text as saved. Add `useLoadDbObjectDefinition.ts` to Files: initialization must not overwrite an existing draft, and stale fetch completion must be rejected after identity/connection changes or user edits. Clean reopen/refetch policy must also be defined.

2. **P1 — D1/D3: scope every key and operation, including reset signals.** Use connection **screen-tab id**, not saved profile id or runtime connection id, throughout store accessors, collectors, subscriptions, open/reopen, discard and cleanup. The same object id can occur in two connection tabs. Leaving `pendingObjectEditorResets` keyed by window id preserves cross-tab collisions; remove it when store-driven rendering makes it unnecessary, or scope it by `(tabId, draftKey)` and clean/re-key it. Centralize key/window-id derivation without lossy parsing of object ids containing colons. A create key must remain stable when kind/name/schema changes. Seed create state when opening, so immediate save/close before pane effects run is deterministic; collectors should be read-only, not manufacture missing drafts as today's collector does.

3. **P1 — D3: resolve saved identity safely before re-keying.** `makeDatabaseObjectId` (`src/lib/databaseObjects.ts:129–138`) includes kind, schema, name, routine signature and trigger table.
